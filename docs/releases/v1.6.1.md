## What's new / 更新內容

**繁體中文**
- **推理強度和加速擴大到所有工具**：agent 列、看板和性能分析卡現在涵蓋所有有本機資料的工具，新增 omp、OpenClaw、Kimi Code CLI、ZCode、Antigravity 和 Factory Droid 記錄的值。
  - Grok Build、WorkBuddy 和 Hermes Agent 只記錄工作階段目前的推理強度，所以顯示的是當下的值。
  - 本機沒有資料的項目維持未知，不會猜測：Pi、DeepSeek Harness、Gemini CLI、Grok Build 和 WorkBuddy 沒有加速資料。
- **設定值**：只寫在設定檔裡的值（Gemini CLI、Antigravity、WorkBuddy、Hermes Agent，以及 Linux 上 Codex 的 `service_tier`）會用虛線膠囊顯示並標「設定值」，因為 agent 不一定實際使用它。設定值不計入歷史和統計，也不會上報。
- **用量歷史**：更新後會重新分析一次，舊紀錄也會補上這些工具的推理強度和加速。
- **即時上報**：推理強度明細涵蓋更多工具。Grok Build、WorkBuddy 和 Hermes Agent 的請求在第一次計入時，帶上當下的推理強度。
- **新讀取的本機資料**：都以唯讀方式開啟，不會讀取對話內容：OpenClaw 的 `trace.metadata` 紀錄、WorkBuddy 的 `workbuddy.db`（工作階段的 `thought_level`）、Hermes Agent 的 `state.db`（`reasoning_config`），以及上述工具設定檔裡的對應欄位。

**简体中文**
- **推理强度和加速扩大到所有工具**：agent 行、看板和性能分析卡现在覆盖所有有本机数据的工具，新增 omp、OpenClaw、Kimi Code CLI、ZCode、Antigravity 和 Factory Droid 记录的值。
  - Grok Build、WorkBuddy 和 Hermes Agent 只记录会话当前的推理强度，所以显示的是当下的值。
  - 本机没有数据的项目保持未知，不会猜测：Pi、DeepSeek Harness、Gemini CLI、Grok Build 和 WorkBuddy 没有加速数据。
- **配置值**：只写在配置文件里的值（Gemini CLI、Antigravity、WorkBuddy、Hermes Agent，以及 Linux 上 Codex 的 `service_tier`）会用虚线胶囊显示并标「配置值」，因为 agent 不一定实际使用它。配置值不计入历史和统计，也不会上报。
- **用量历史**：更新后会重新分析一次，旧记录也会补上这些工具的推理强度和加速。
- **实时上报**：推理强度明细覆盖更多工具。Grok Build、WorkBuddy 和 Hermes Agent 的请求在第一次计入时，带上当下的推理强度。
- **新读取的本机数据**：都以只读方式打开，不会读取对话内容：OpenClaw 的 `trace.metadata` 记录、WorkBuddy 的 `workbuddy.db`（会话的 `thought_level`）、Hermes Agent 的 `state.db`（`reasoning_config`），以及上述工具配置文件里的对应字段。

**English**
- **Reasoning effort and speed for every tool.** Agent rows, boards and the performance card now cover every tool with local data, adding what omp, OpenClaw, Kimi Code CLI, ZCode, Antigravity and Factory Droid record.
  - Grok Build, WorkBuddy and Hermes Agent only record a session's latest effort, so that is the value shown.
  - Anything with no local data stays unknown and is never guessed: Pi, DeepSeek Harness, Gemini CLI, Grok Build and WorkBuddy have no speed data.
- **Configured values.** A value that exists only in a config file (Gemini CLI, Antigravity, WorkBuddy, Hermes Agent, and Codex's `service_tier` on Linux) appears as a dashed capsule marked "config", since the agent may not be using it. It never enters history or statistics and is never reported.
- **Usage History.** The history is analysed once after the update, so older records gain effort and speed for these tools too.
- **Live reporting.** The effort breakdown covers more tools. A Grok Build, WorkBuddy or Hermes Agent request carries the session's effort at the moment it is first counted.
- **New local data read.** All of it is opened read-only and no conversation text is read: OpenClaw's `trace.metadata` rows, WorkBuddy's `workbuddy.db` (a session's `thought_level`), Hermes Agent's `state.db` (`reasoning_config`), and the matching keys in those tools' config files.

**日本語**
- **推論の強さと高速化をすべてのツールに拡大**：エージェントの行、ボード、性能カードは、ローカルにデータがあるすべてのツールに対応しました。omp、OpenClaw、Kimi Code CLI、ZCode、Antigravity、Factory Droid が記録する値を新たに表示します。
  - Grok Build、WorkBuddy、Hermes Agent はセッションの最新の推論の強さしか記録しないため、その値を表示します。
  - ローカルにデータがない項目は不明のままで、推測はしません：Pi、DeepSeek Harness、Gemini CLI、Grok Build、WorkBuddy には高速化のデータがありません。
- **設定値**：設定ファイルにしかない値（Gemini CLI、Antigravity、WorkBuddy、Hermes Agent、および Linux の Codex の `service_tier`）は、エージェントが実際に使っているとは限らないため、破線のカプセルに「設定値」と付けて表示します。設定値は履歴や統計に含まれず、送信もされません。
- **使用履歴**：更新後に一度再分析し、過去の記録にもこれらのツールの推論の強さと高速化を反映します。
- **ライブレポート**：推論の強さの内訳の対象ツールを広げました。Grok Build、WorkBuddy、Hermes Agent のリクエストには、最初に集計された時点の推論の強さを付けます。
- **新たに読み取るローカルデータ**：すべて読み取り専用で開き、会話の内容は読みません：OpenClaw の `trace.metadata` 行、WorkBuddy の `workbuddy.db`（セッションの `thought_level`）、Hermes Agent の `state.db`（`reasoning_config`）、および上記ツールの設定ファイルの該当キー。
